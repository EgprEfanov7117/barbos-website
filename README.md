# NOVARY

Сайт цифровой студии: главная, разработка, дизайн и креативы. Графитовый фон, светлая прямая типографика, оранжевые акценты. Примеры кофейни и цветочной мастерской — учебные концепты.

## Публикация

Существующий проект Cloudflare Pages: `novary`, https://novary.pages.dev/. Репозиторий: `EgprEfanov7117/novary-website`, production-ветка `main`. Команда сборки — `npm run build:cloudflare`, публичный каталог — `dist/client`. Настройки платформы и D1-привязка — `wrangler.jsonc`.

Версия Wrangler закреплена в зависимостях. `scripts/build-cloudflare.mjs` заранее собирает Functions в `dist/client/_worker.js/` (Pages advanced mode), чтобы автоматическая публикация и локальные preview использовали один компилятор и одинаковую поддержку Node API. Каталог Worker не является публичной статикой.

Обработчик формы: `functions/api/leads.js` → `cloudflare/leads.mjs`. Он отправляет заявку в Telegram и через SMTP Яндекса. Подтверждение показывается после успешных ответов обоих сервисов. Контакт, задача, направление, пакет и опции передаются владельцу; стоимость рассчитывается по серверному каталогу.

В Cloudflare почтовое соединение открывает `cloudflare/smtp-socket.mjs`: среда сама подключается к имени сервера, без проверки сетевых интерфейсов из Nodemailer. TLS и проверка сертификата обязательны; готовое соединение передаётся Nodemailer только после защищённого рукопожатия. Это устраняет обнаруженный при публикации сбой определения сетевого адреса.

D1 `novary-site-leads`, привязка `LEADS_DB`, схема `cloudflare/schema.sql`: только хеш заявки, статусы отправок, срок блокировки параллельного повтора и счётчики частоты. Контакт и текст задачи в D1 не сохраняются. Подтверждения хранятся сутки, счётчики — 10 минут; очистка выполняется при новых запросах. IP в счётчиках хранится в виде хеша с серверным секретом. Повторяет только неподтверждённый канал. Если внешний сервис принял сообщение, но соединение оборвалось до подтверждения, возможна повторная доставка; номер заявки позволяет сопоставить уведомления.

Секреты Cloudflare задаются отдельно для Preview/Production: TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, LEAD_EMAIL_FROM, LEAD_EMAIL_TO. Никогда не помещайте значения в Git, публичные файлы или VITE-переменные. Форма принимает только запросы с того же origin, ограничивает длину полей и частоту попыток.

Демонстрационный бот кофейни внутри концепта остаётся локальным примером. Альтернативные Telegram-кнопки пока направляют к форме с предложением указать Telegram для ответа; личные контакты получателей в интерфейсе не опубликованы.

## Локальный запуск

```sh
npm ci
npm run dev -- --host 0.0.0.0 --port 4173
```

Для реальной локальной отправки создайте `.env.local` по `.env.example`. Файл исключён из Git. Без настроенных каналов сервер вернёт ошибку и сохранит введённые данные в форме для повтора.

Локальный Node-сервер готовой сборки:

```sh
npm run build
npm start
```

`npm start` использует `server/index.mjs`, `.env.local` при наличии и `dist/client/`. HOST по умолчанию 127.0.0.1, PORT — 4173. Локальный сервер использует память процесса для повторов в пределах 15 минут; облачный обработчик использует D1.
